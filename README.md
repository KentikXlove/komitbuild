

# 🛠️ komitbuild

**Универсальный CLI-билдер для упаковки Python-проектов в `.exe`**  
на базе [PyInstaller](https://pyinstaller.org/) с гибкой настройкой через JSON.

---

## 📦 Возможности

- Сборка в **один файл** (`--onefile`) или **папку** (`--onedir`).
- Конфигурация в удобном **JSON** – все параметры PyInstaller под рукой.
- Автоматическое включение дополнительных файлов и папок (ресурсы, шаблоны, базы данных).
- Поддержка **иконки** `.ico`, **файла версии**, **скрытых импортов**.
- **Очистка** временных файлов сборки (`build`, `dist`, `*.spec`) одной командой.
- **Просмотр** текущей конфигурации.
- **UPX-сжатие** (опционально) для уменьшения размера исполняемого файла.
- Простой интерфейс командной строки с подсказками.

## 🚀 Установка

### Через git (рекомендуется)
```bash
pip install git+https://github.com/KentikXlove/komitbuild
```

## 📘 Использование

После установки в вашем окружении появляется консольная команда `komitbuild`.

```bash
komitbuild [command] [options]
```

### Доступные команды

| Команда | Описание |
|---------|----------|
| `build [config]` | Собрать проект по конфигурационному файлу (по умолчанию `build_config.json`). Если файла нет – будет создан пример. |
| `clean`          | Удалить все временные папки (`build`, `dist`) и `.spec`-файлы. |
| `info [config]`  | Вывести содержимое конфигурационного файла в отформатированном виде. |
| `help`           | Показать справку по всем командам и опциям. |

---

### Примеры

```bash
# Собрать проект с конфигом по умолчанию
komitbuild build

# Собрать с пользовательским конфигом
komitbuild build my_config.json

# Собрать и передать дополнительные аргументы PyInstaller
komitbuild build --extra --debug --log-level INFO

# Очистить временные файлы
komitbuild clean

# Посмотреть текущую конфигурацию
komitbuild info

# Создать пример конфигурации (если не существует)
komitbuild build --create-example
```

## ⚙️ Конфигурационный файл

Файл – это JSON-объект со следующими полями (все опциональны, но некоторые сильно рекомендуются):

| Поле | Тип | Описание |
|------|-----|----------|
| `project_name` | строка | Имя выходного `.exe`-файла и папки (если `onedir`). |
| `main_script` | строка | Путь к главному скрипту (точке входа) относительно корня проекта. |
| `output_dir` | строка | Папка, куда будет помещён результат (по умолчанию `dist`). |
| `build_mode` | `"onedir"` или `"onefile"` | Режим сборки. |
| `console` | логическое | `true` – показывать консольное окно, `false` – скрыть (для GUI-приложений). |
| `clean_build` | логическое | Удалять временные файлы перед сборкой (рекомендуется). |
| `additional_files` | массив объектов | Список файлов/папок для включения в сборку. Каждый объект: `source` – путь, `destination` – куда положить внутри сборки, `type` (не обязателен). |
| `additional_binary_files` | массив объектов | Аналогично, но для бинарных файлов (`.dll`, `.so`, `.dylib`). |
| `hidden_imports` | массив строк | Модули, которые PyInstaller не видит автоматически (динамические импорты). |
| `exclude_modules` | массив строк | Модули, которые нужно исключить из сборки (уменьшает размер). |
| `icon` | строка | Путь к `.ico`-файлу для иконки приложения. |
| `version_file` | строка | Путь к текстовому файлу с информацией о версии (формат PyInstaller). |
| `upx` | логическое | Использовать UPX-сжатие (требуется установленный UPX и правильный путь в коде). |
| `runtime_hooks` | массив строк | Пути к хукам времени выполнения (`.py`-файлы). |
| `pathex` | массив строк | Дополнительные пути для поиска модулей. |
| `datas` | массив объектов | Расширенный формат для `--add-data` (можно использовать вместо `additional_files`). |

### Пример конфигурации (автоматически создаётся при первом запуске)

```json
{
  "project_name": "MyApp",
  "main_script": "run.py",
  "output_dir": "dist",
  "build_mode": "onedir",
  "console": false,
  "clean_build": true,
  "additional_files": [
    {"source": "templates", "destination": "templates", "type": "directory"},
    {"source": "data", "destination": "data", "type": "directory"}
  ],
  "additional_binary_files": [],
  "hidden_imports": [],
  "exclude_modules": [],
  "icon": "icon.ico",
  "version_file": null,
  "upx": false,
  "runtime_hooks": [],
  "pathex": [],
  "datas": []
}
```

## 📂 Структура проекта

Рекомендуется размещать `build_config.json` в **корневой папке вашего проекта** (там же, где и основной скрипт).  
Во время сборки все пути в конфигурации интерпретируются **относительно текущей рабочей директории** (т.е. той, где вы запускаете `komitbuild`).

---

## 🧹 Очистка

Команда `komitbuild clean` удаляет:
- папки `build/` и `dist/`
- все `.spec`-файлы в корне проекта

Это полезно, чтобы начать сборку с чистого листа или освободить место.

## 🔧 Требования

- **Python 3.6+**
- **PyInstaller** (устанавливается автоматически как зависимость, если вы ставите пакет через `pip`)
- **UPX** (опционально) – для сжатия, скачайте с [официального сайта](https://upx.github.io/) и укажите путь в коде (по умолчанию `C:\\upx`, но вы можете отредактировать код или передать свой путь через `--extra --upx-dir`).

## 🐞 Устранение неполадок

1. **Ошибка «PyInstaller не установлен»**  
   Установите его вручную: `pip install pyinstaller`

2. **Не найден главный скрипт**  
   Убедитесь, что поле `main_script` указывает на существующий файл относительно корня.

3. **Проблемы с путями в `additional_files`**  
   Используйте относительные пути без начального `./` или `../`. Все пути считаются от корня проекта (текущей рабочей директории).

4. **Иконка не применяется**  
   Проверьте, что файл имеет расширение `.ico` и находится по указанному пути. PyInstaller требует именно ICO-формат.

5. **Сборка падает с ошибкой импорта**  
   Добавьте недостающие модули в `hidden_imports` или `pathex`.

- Для добавления новых команд достаточно обновить `cli.py` и реализовать соответствующую логику.
- Код документирован и снабжён русскоязычными сообщениями (можно перевести на английский при необходимости).
